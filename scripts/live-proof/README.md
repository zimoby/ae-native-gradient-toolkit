# AE 26.3 Live-Proof Harness

This directory is the external, fail-closed harness for validating generated native gradient presets in After Effects 26.3. It is not shipped in the npm package.

## Safety boundary

- Offline commands may validate config, generate a token-scoped preset, and generate a dispatch file. They do not source AE helpers.
- Live commands require both `--execute` and `AE_NATIVE_GRADIENT_LIVE_APPROVED=<runToken>`.
- Set that environment variable only after explicit approval for the current session and exact scratch project.
- The runner accepts only an absolute, normalized config path inside a scratch directory whose basename contains `runToken`.
- The runner rejects symlinked config, helpers, project, preset, and implementation files.
- A global atomic lock at `/private/tmp/ae-native-gradient-live-proof.lock` prevents concurrent harness runs. A pre-existing lock is never removed automatically.
- Every live phase performs a read-only `ae_run` identity/version probe before invoking exactly one generated `ae_file_json` dispatch.
- There are no automatic mutation retries. Preserve the dispatch, config, preset, and failure manifest after any host failure.
- `cleanup` removes only token-owned layers/items and intentionally does not save; only `proof-save-readback.jsx` may save. A final target-absent save/readback phase proves the clean persisted baseline.

## Offline verification

```bash
npm run test:live-proof
```

No AE helper is read by the focused suite. It verifies:

- strict schema, token, path, AE-version, descriptor, and gradient validation;
- deterministic preset creation and exact resume/tamper behavior;
- reviewed-script dispatch allowlisting and temporary-global cleanup;
- generated dispatch JavaScript syntax;
- no-clobber output behavior;
- `--validate-only` isolation;
- denial of `--execute` before helper lookup when the approval token does not match.

## Config lifecycle

The JSON object is strict; unknown keys are rejected. Required root keys:

- `schemaVersion`: `1`
- `runToken`: 8–64 safe characters
- `scratchRoot`: absolute token-marked directory
- `projectPath`: exact saved `.aep` child of `scratchRoot`
- `evidenceRoot`: child directory of `scratchRoot`
- `expectedAeVersion`: `26.3` or a more specific 26.3 build string
- `expectedTargetPresent`: `true` for normal readback/action phases and cleanup preflight; `false` only for post-cleanup save/readback
- `expectedCandidateCount`: exact saved-AEP native-gradient candidate count, restricted to `0` or `1`; use `0` for baseline, post-Undo, and post-cleanup readback, and `1` after Apply
- `phase`: `setup`, `apply`, `save-readback`, `undo`, or `cleanup`
- `kind`: `fill` or `stroke`
- `stopCount`: `2`, `3`, or `8`
- `gradient`: canonical `schemaVersion: 1` gradient object with equal color/alpha counts
- `presetPath`: `ae-gradient-<runToken>-<kind>-<stopCount>.ffx` inside `scratchRoot`
- `presetSha256`: lowercase SHA-256 of deterministic generated bytes
- `target`: `null` only for `setup`; otherwise the exact descriptor returned by setup

The target descriptor includes comp ownership, comp/layer IDs and names, layer index, and equal-length property-index/match-name paths ending in the kind-specific gradient parent plus `ADBE Vector Grad Colors`.

Use a placeholder 64-character lowercase hash only for the explain step, then replace it with the reported deterministic hash:

```bash
node scripts/live-proof/prepare-preset.mjs --config /absolute/token-root/config.json --explain
node scripts/live-proof/prepare-preset.mjs --config /absolute/token-root/config.json --write
```

`--write` publishes once and fails if the destination exists. The live apply runner uses “exact existing or create once” behavior and rejects any drift.

## Offline phase validation

```bash
scripts/live-proof/run-proof.sh \
  --config /absolute/token-root/config.json \
  --phase apply \
  --validate-only
```

This writes a unique dispatch inside the token root and reports the config, implementation, and dispatch hashes. It does not inspect or call AE helpers.

## Live phase command

Do not run until the current session has explicit approval for the exact project and token.

```bash
AE_NODE="$(command -v node)" \
AE_HELPERS="$HOME/.ae-helpers.sh" \
AE_NATIVE_GRADIENT_LIVE_APPROVED=<runToken> \
  scripts/live-proof/run-proof.sh \
    --config /absolute/token-root/config.json \
    --phase <phase> \
    --execute \
    --home "$HOME" \
    --helpers "$HOME/.ae-helpers.sh" \
    --timeout-ms 60000
```

The exact Node path must be verified live before evidence collection. Do not assume the example path exists.

## Phase protocol and stop states

1. `setup`
   - Requires exact saved project path and clean project.
   - Finds or creates one token-owned comp, removes only same-token proof layers, creates one fill/stroke target, and returns the target descriptor.
   - Copy the returned descriptor into the next config. Preserve `compCreatedByHarness`.
2. `save-readback` baseline
   - Resolves the exact target and saves the exact current project.
   - Returns scriptable sibling/selection/item inventory.
   - Runner inventories the saved AEP and requires zero candidates because AE 26.3 does not serialize an untouched default gradient as `GCky`.
3. `apply`
   - Runner verifies/generates exact preset bytes and SHA immediately before dispatch.
   - Script requires clean project, static target, exact IDs/path/match names, and bounded preset.
   - It snapshots and restores selection around one `applyPreset` call in one undo group.
   - Runner waits at least 1000 ms and polls read-only state to stability.
4. `save-readback` after apply
   - Produces accepted saved-project evidence and requires one unique valid AEP candidate.
   - Compare the generated and saved gradient models after applying `Math.fround` to every numeric field. AE may rewrite equivalent float32 values with shorter XML decimal spellings, such as `0.1899999976158142` to `0.19`.
5. `undo`
   - Calls command 16 once after full preflight; no retry.
   - Runner waits at least 1000 ms and polls to stability.
6. `save-readback` after undo
   - Proves the reverted saved project and requires the zero-candidate baseline inventory.
7. `cleanup`
   - Removes only the exact token-owned layer, or the exact harness-created comp only when it still contains exactly that one layer.
   - Does not save.
8. `save-readback` after cleanup
   - Set `expectedTargetPresent` to `false` while retaining the prior target descriptor.
   - Proves the target layer/owned comp is absent, saves, asserts clean state, and requires zero gradient candidates in the saved AEP.

Stop immediately on:

- version/project/active-comp identity drift;
- dirty-state mismatch for setup/apply/cleanup;
- missing or duplicate token-owned identity;
- descriptor or match-name mismatch;
- non-static target;
- preset realpath/hash/size drift;
- helper timeout/non-JSON/failure response;
- saved AEP unique-inventory failure;
- unstable state polling;
- existing global lock.

## AE 26.3 proof matrix

Run serially in one clean token-owned scratch project:

- fill: 2, 3, 8 stops;
- stroke: 2, 3, 8 stops.

For each case, reset through setup, record the zero-candidate baseline, apply and save/read back one unique candidate, compare the generated and saved values with float32 semantics, undo and prove the zero-candidate baseline, clean up, then save/read back target absence. Do not advance after any skipped or partial phase. Record exact config, dispatch, preset, template, implementation, and saved-AEP hashes in the evidence ledger.
